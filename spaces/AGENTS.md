# BaneySpaces agent rules

BaneySpaces is a macOS workspace manager: ⌘1–9 switch workspaces, ⌘⇧1–9 move a window, plus
the ⌘Tab window bar, the Workspace Dock and the launcher. Donovan uses it all day, so a bug he
sees twice costs more than a slow release.

## Done

A change is done when steps 1 to 3 pass on its branch and step 4 passes on `main` right after merge (only `main` is installed on Donovan's Mac). If step 4 fails after merge, revert the merge first, then fix:

1. `swift test`
2. `scripts/bench.sh` (median no-op switch under 40 ms; p90 of your real switches in `timing.log` under 250 ms).
   Exit 3 means fewer than 20 real switches since the build started: make them, or report "real-use budget unchecked".
   Then `scripts/speed-report.sh` (read-only; also daily): the last day of `timing.log` against every budget in
   `spec/speed.json` `spacesTiming` (switch, parked and each `open` kind, p50/p90/p99), and a count of dock stuck-open and
   ⌘Tab switcher-wrong lines in `trace.log` that must be 0. Exit 1 is a miss: put its table in the report. Until the
   switch, parked and dock budgets are met (gaps P1 to P3) a speed miss is reported, not a merge blocker; a non-zero
   glitch count is a regression and follows the ledger rule below. `SpeedBudgetTests` fails when the app logs a kind with
   no budget.
3. For anything that hides, parks, moves or restores windows: `swift scripts/motion-probe.swift <a> <b>`
   with Helium or Ghostty on one of the two workspaces. It must print "no window slid".
   For anything that decides which windows exist or where they live: `swift scripts/closed-window-probe.swift <empty n>`.
   For the drag to the top of the screen (`TopDrag`, `TopDragWatcher`, the viewer's carrying mode):
   `swift scripts/top-drag-probe.swift`. It takes the pointer for ten seconds; run it while Donovan is away.
   For a window dragged down to the dock (`DockCarry`, `WorkspaceDock.carryMoved`/`endCarry`, the watcher's
   `onCarry`): `swift scripts/dock-drag-probe.swift`, also while he's away.
   For a filled window dragged by its title bar or a drag's release (`FullScreenFill.dragStart`, `Spaces.unfillForDrag`,
   `DragRelease`, `Spaces.correctAfterDrag`, `TopDragWatcher.onDragEnd`): `swift scripts/fill-drag-probe.swift --self-test`
   (no pointer), then `swift scripts/fill-drag-probe.swift [--record]`, which refuses to run until the Mac has been idle
   ten minutes. Each case fails if its precondition (macOS filled it, Polycarp filled it, the overview let it go over no
   workspace, it was let go hanging off the edge) didn't happen or the trace lacks the lines that show Polycarp took part.
   Case 5 fills a window by a drag to the top and watches it from mouse-up, with no gap, for 3 s: it fails if macOS
   didn't fill it within 1 s or the filled frame changes after, and with Polycarp running, unless the trace shows
   Polycarp saw the drag rest at the top and never moved or filled the window. Its arms split the lower-half jump's cause:
   `--no-polycarp` (Polycarp quit first, frames only), `--chromium` (a Chrome for Testing window it launches with its own
   profile; it installs nothing, stops if Chrome for Testing is missing, and always quits it and removes the profile), or
   both. Either flag runs case 5 alone (`--no-polycarp` also case 6). The rest at the top opens the overview, so case 5
   reads the trace to fail a move Polycarp made as Polycarp's, never as the jump. Case 6 lets a window go blind at the
   left edge and prints macOS's pause before it half-tiles; set `DragRelease.sideTileStillLooks` from that number.
   For the dock's own motion or the "+N" list/strip panel (`DockSide`, `DockMotion`, `WorkspaceDock.show/hide/syncSide`):
   `swift scripts/dock-motion-probe.swift` (no pointer; it shows the dock for about four seconds, so run it
   when Donovan has been idle 10 minutes; it needs `dockURLCommands` on and a tile with more than four apps).
   For anything that decides what each display shows (`Workspaces.shown`, `displays`, `carry`,
   `noteMovedAcrossDisplays`): `swift scripts/displays-probe.swift` with two displays (Sidecar counts).
4. The gesture Donovan reported, done live on his Mac (the real keys, the real hold, the real
   click), with the result read back from the screen, `trace.log` or `state.json`. Pointer and key
   probes run only when he has been idle 10 minutes (`ioreg -c IOHIDSystem` HIDIdleTime); otherwise
   the PR lists the exact steps for him to try and says "untested live". Agent tools act only on
   the agent workspace, so they can't stand in for a gesture on his own workspaces. Only `main` is installed on his Mac: branches build and test,
   and never run `make install` there.

Unit tests and CI only prove the plan logic. They have never caught a visible bug here. If step 4
can't run, say "untested live" in the report and don't call the bug fixed.

## Run and check

Crash-loop guard (`CrashLoopGuard`, checked in `main.swift` before the delegate exists): a launch
whose run is still in `~/Library/Application Support/BaneySpaces/crash-ledger.json` (no clean quit)
counts as a crash. After 3 within 5 minutes the next launch puts Mission Control, the macOS Dock and
the drag to the top back, says so in an alert (Quit, or Start Anyway, which clears the crashes) and
doesn't start. `--render` keeps its own `crash-ledger-render.json` and exits 75 instead. Knobs:
`defaults write com.baney.polycarp crashLoopLimit -int N` (0 never stops) and
`crashLoopWindowMinutes -float M`.

Logs: every guarded launch writes `launch: BaneySpaces <version> (<commit>), normal|setup|render, pid N`,
then `crash loop: start|stop (<mode>), N of 3 crashes in 5 minutes, ledger ~/…/crash-ledger.json`. A stop
adds `crash loop: Dock and drag to the top restored, Mission Control saved settings restored|no saved settings changed` (its time is
when Mission Control came back), then `Quit, staying stopped` or `Start Anyway, N crashes forgiven`; a clean
quit writes `crash loop: clean quit (<mode>), pid N cleared from the ledger`. The text lives in
`CrashLoopReport` (pinned by `CrashLoopReportTests`). Read it back from the file
(`grep -E 'launch:|crash loop:' ~/Library/Application\ Support/BaneySpaces/trace.log`, epoch seconds first;
the file rotates at 200 KB into `trace.log.1` and `trace.log.2`) or the unified log, which survives rotation:
`/usr/bin/log show --last 1h --predicate 'subsystem == "com.baney.polycarp"' | grep -E 'launch:|crash loop:'`.
The crash itself is in `~/Library/Logs/DiagnosticReports/BaneySpaces-*.ips`. These lines hold counts, pids,
the build and `~` paths, never window titles or the user name; keep it that way.


## Stable releases

Do not mark a GitHub release as Latest / stable until `scripts/soak-check.sh` prints `SOAK PASSED` on rectory1 (or another Mac with the build installed and running) and Sol APPROVE includes the soak receipt path. `--ci` mode is for the script self-check only; it is not a live soak. Never unpublish or retag an already-published stable (including 0.3.0). Updater defaults to the channel the build came from (`PolycarpChannel`; a nightly or the old preview follows nightly), else stable (`UpdateChannel.stable`); a choice made in Settings wins.

Updates must never reset macOS permissions (TCC). Never distribute an ad-hoc build (`codesign --sign -`,
`BANEYSPACES_ADHOC=1`) as an update or attach one to any release, nightly included: those builds are for
local work and CI checks only. Release assets must satisfy `scripts/release-requirement.txt`
(`release.sh`, `package.sh`, `verify-release.sh` and `install.sh` check it), and `install-app.sh`
refuses an ad-hoc build over an installed copy.

## Shared core and Windows (`crates/`, `spec/`, `platforms/windows`)

A change there is done when `cargo test --workspace --locked` passes. A rule that is not in `spec/` does not ship on
one platform alone. The Linux and Omarchy desktop is retired; its last snapshot is in the archived baney75/baneyspaces.
`spec/` still lists its key row as a record. Linux desktop work is retired.
